## 以降は設計書

## 1. システム概要
本システムは、キャチロボ出場機体（2機体・各3軸・計6軸のDynamixel）を、PS4コントローラーからの入力（ROS 2 `/joy` トピック）に基づき速度制御で駆動するためのリアルタイム制御システムである。

開発・テストフェーズではノートPC環境を使用しssh接続してkhadasで動かす、最終運用フェーズではkhadas（Linux環境）へプログラムを移植・集約して運用する。

---

## 2. システム構成・ハードウェア構成

### 2.1 ハードウェア構成
* **メインプロセッサ**: khadas（Ubuntu 22.04 LTS, ROS 2 Humble）
* **入力デバイス**: PS4コントローラー × 2台（bluetooth)
* **アクチュエータ**: Dynamixel Xシリーズ × 6台（1機体あたり3台: X軸, Y1軸, Y2軸）
* **通信インターフェース**: U2D2（USB to RS485/TTL変換）

### 2.2 システム配置図
[ PS4 Controller A ] ──(bluetooth)──┐ ├──> [ khadas) ] ──(USB/U2D2)──> [ Dynamixel x6 ] [ PS4 Controller B ] ──(bluetooth)──┘ ├── joy_node (x2) [Publisher] └── dual_robot_controller [Subscriber]

## 3. ソフトウェア設計

### 3.1 キーコンフィグ（入力割り当て）
1本のアナログスティックでX/Y制御（直角カルテシアン操作）を行いつつ、Y軸（Y1, Y2）の独立操作を可能にするため、以下の割り当てとする。

| コントローラー入力               | 割り当てる動作    | 制御仕様・備考                  |
| ----------------------- | ---------- | ------------------------ |
| **左スティック X軸 (axes[0])** | **X軸移動**   | 左右でX軸モータの目標速度を変更         |
| **左スティック Y軸 (axes[1])** | **Y1軸移動**  | 前後でY1軸モータの目標速度を変更        |
| **右スティック Y軸 (axes[4])** | **Y2軸移動**  | 前後でY2軸モータの目標速度を変更        |
| **L2[2] / R2 トリガー[5]**  | **微修正モード** | 押下時に最高速度を50%へ減衰（精密位置決め用） |
|                         | 緊急停止       |                          |
### 3.2 制御パラメータとデータ構造（Pythonクラス非使用設計）
可読性と汎用性を担保するため、共通処理関数と辞書型設定構造を採用する。

```python
# 機体A の「設定」と「状態（目標速度）」を管理する辞書
robot_a = {
    'name': 'robot_a',
    'joy_topic': '/joy_a',
    'dxl_ids': [1, 2, 3],      # [X軸, Y1軸, Y2軸]
    'invert': [1, -1, 1],      # 回転方向反転フラグ
    # --- 以下が動的に変わる目標速度（状態） ---
    'target_vel': [0, 0, 0],   # [X軸速度, Y1軸速度, Y2軸速度]
    'slow_mode': False,        # 微修正モード（L2/R2が押されているか）
}

# 機体B も同じ構造で作る
robot_b = {
    'name': 'robot_b',
    'joy_topic': '/joy_b',
    'dxl_ids': [4, 5, 6],
    'invert': [1, -1, 1],
    'target_vel': [0, 0, 0],
    'slow_mode': False,
}
```

3.3 制御ロジックの要件
不感帯処理 (Deadzone): スティックの入力値が |val| < 0.05 の場合は 0.0 に補正し、微小振動による意図しない暴走を防止する。

同期送信 (GroupSyncWrite): 各機体の3軸（X, Y1, Y2）への速度命令は、Dynamixel SDKの GroupSyncWrite パケットを使用し、1通信フレームで一括送信する。

安全停止処理

ノード終了時（KeyboardInterrupt）および安全保護割り込み時は、全軸へ速度 0 を送信し、トルク処理を安全に終了させる。

### 関数
[/joy_a 受信] ──> joy_a_callback ──┐
                                     ├──> update_robot_velocity ──> 辞書(robot_a / robot_b) の target_vel を書き換える
 [/joy_b 受信] ──> joy_b_callback ──┘                                        │
                                                                             ▼ (0.05秒ごとに自動実行)
                                                                    timer_callback ──> 6軸分一括送信 (GroupSyncWrite)

#### 1. ヘルパー関数（汎用処理）

- **`apply_deadzone(val, threshold=0.05)`**
    - **役割:** スティックの微小振動（ブレ）を無視する不感帯処理。
    - **入力:** スティックの生の傾き値（-1.0 ～ 1.0）
    - **出力:** 不感帯を適用した値（絶対値が 0.05 未満なら `0.0`）
        

#### 2. ロジック処理関数（使い回すメイン関数）

- **`update_robot_velocity(robot_dict, joy_msg)`**
    - **役割:** 受信したコントローラー入力から目標速度を計算し、辞書の中身（`target_vel`）を更新する。
    - **ポイント:** `robot_a` と `robot_b` の両方で**全く同じこの関数**を使い回します。
        
    - **内部処理:**
        - L2/R2ボタンが押されているか確認し、最高速度を50%にする（微修正モード）。
        - 各スティックの値に `apply_deadzone` と `invert`（反転フラグ）を掛けて速度を計算。
        - `robot_dict['target_vel'] = [vx, vy1, vy2]` のように辞書を更新。
            

#### 3. コールバック関数（ROS 2の受信窓口）

- **`joy_a_callback(msg)`**
    
    - **役割:** `/joy_a` トピック（コントローラーA）を受信した時に呼ばれる。
    - **処理:** `update_robot_velocity(robot_a, msg)` を実行するだけ（1行で終わる）。
        
- **`joy_b_callback(msg)`**
    
    - **役割:** `/joy_b` トピック（コントローラーB）を受信した時に呼ばれる。
    - **処理:** `update_robot_velocity(robot_b, msg)` を実行するだけ（1行で終わる）。
        

#### 4. タイマー関数（Dynamixel通信・一括送信）

- **`timer_callback()`**
    
    - **役割:** 定期周期（例: 20Hz / 0.05秒ごと）で自動的に実行される通信関数。
        
    - **処理:**
        - `robot_a` と `robot_b` の最新の `target_vel` を参照。
        - Dynamixel SDK の `GroupSyncWrite` に6軸分（3軸 × 2機）の速度データを追加。
        - シリアルバスへ一括送信（`txPacket()`）する。
            

#### 5. 全体管理関数

- **`main()`**
    - **役割:** ROS 2ノードの初期化、Dynamixelの通信ポート開通、上記のコールバックやタイマーの登録、終了時の安全処理（全軸トルクオフ/速度0送信）を行う。
